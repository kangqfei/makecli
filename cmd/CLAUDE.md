## 渲染约定
- 表格统一用 `github.com/olekukonko/tablewriter`（边框 + Header），禁止用 stdlib `text/tabwriter`
- key-value 头部信息（File / Name / App 等）用 `fmt.Printf("%-N s %s\n", ...)` 平铺，不进表格
- 写新输出前先 grep 邻居命令的渲染方式再动手，避免风格漂移

## 全局标志（root PersistentFlags）
- `--profile string`（default "default"）— 凭证 profile 名，绑定全局变量 `cmd.Profile`（包级 `var Profile = "default"`，单测无需 cobra 解析也能用）
- `--access-token string` / `-t` — access token 覆盖，绑定 `cmd.AccessToken`；取值链 **flag > `$MAKE_ACCESS_TOKEN` > credentials[profile].access_token**（三者同名，收口在 client.go resolveAccessToken，resolveProfile / configure verify / whoami 共用）。覆盖只替换凭证本身，tenant / operator / URL 仍取自 `--profile` 的 config 段；覆盖态下 login 写文件不会生效，故 whoami 不再自动重登录、configure verify 与鉴权引导回显 token 来源（flag/env/credentials）。flag 值会留在 shell history / ps，CI 用环境变量
- `--meta-server-url string` — Meta Server **主机地址**（只到主机名），绑定 `cmd.MetaServerURL`；取值链 **flag > `$MAKE_META_SERVER_URL` > profile config meta-server-url > 环境内置地址**（收口 client.go metaServerURL，最后一级是默认值不是配置项）；网关前缀 `/api/make` 由 `withGateway` 自动补齐
- 代码仓库服务（make-repo）主机**无 flag 级**——它是部署实现细节，不值得占全局 flag；取值链 **`$MAKE_REPO_SERVER_URL` > profile config repo-server-url > 环境内置地址**（收口 client.go repoServerURL，env 级留给 CI/测试覆盖）
- 两条覆盖类 flag（access-token / meta-server-url）可配置来源同构：flag、`$MAKE_<KEY>` 环境变量、profile 文件，help 文案统一为 `<noun> (overrides $ENV and the profile <file>)`
- `--context string` — 后端 context（dev/test/production），绑定 `cmd.Context`；取值链 **flag > `$MAKE_CLI_CONTEXT`（常量 EnvContext，前缀 MAKE_CLI_ 因选后端是工具自身行为）> `[settings] context` > 默认 production**（收口 client.go resolveContext，login / trace / daemon / configure resolve|verify / context show 共用）；配置文件仍是旧键 `[settings] environment` 时解析链**报错指引 `makecli doctor --fix`**（doctorFixHint 常量，与 doctor 自身的 fixable 提示同文），不静默回退（旧配置写着 dev 却落到 production 是最坏兼容）。后端 URL 五件套兜底来自 `config.Context` preset。**词汇约定**：context = 连哪套 Make 后端；environment 只指 app 的部署环境（beta/production，`app deploy` / `app delete` 的本地 `--env`）——两词各占一层，全局 flag 改名 `--context` 也消除了与本地 `--env` 的同名遮蔽
- `--debug`（隐藏）— 输出 curl 调试信息，绑定 `cmd.DebugMode`

三者都不再从 `runXxx` 签名穿越，统一由 `newClientFromProfile()`（零参数）在内部直接读取全局。新增子命令时：
- 禁止声明本地 `--profile`
- `runXxx` 函数不要带 profile 参数
- 客户端构建调用 `newClientFromProfile()` 即可，不传 profile/server/env 参数；每命令横切选项（如 dry-run）经 `newClientFromProfile(api.WithDryRun(dryRun))` 变参注入
- 单测需要切换 profile 时用 `setProfile(t, "name")`（stdout_test.go），t.Cleanup 自动还原
